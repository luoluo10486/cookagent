### 4.6 M2-1 Chat SSE 持久化回放业务验证

Chat 创建兼容入口与持久化 SSE 入口分开：

```text
POST /api/chat/runs
GET /api/agent-runs/{runId}/stream
```

`POST /api/chat/runs` 创建数值型 V1 Run；持久化事件统一由
`/api/agent-runs/{runId}/stream` 提供，进入 PostgreSQL-backed
`V1RuntimeEventService`。旧字符串 Run 保留 RuntimeGateway 兼容路径。浏览器断线时优先发送服务返回的稳定 SSE ID：

```http
Last-Event-ID: sse_<previous-event-id>
```

服务端也接受数值游标，便于本地业务验证。已实际验证 `Last-Event-ID: 5` 能从本地 deterministic Run 回放后续 `run.completed` 终态，且终态只出现一次。控制器定向测试命令为：

