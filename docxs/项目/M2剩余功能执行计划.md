## 2. 已确认决策

1. SQL Agent 首期只读取当前用户自己的饮食记录、摄入汇总、餐食计划和购物清单，以及公共营养目录和公共知识元数据。
2. 用户、认证、令牌、密钥、完整审计内容、系统配置和其他用户数据不进入 SQL Agent 可见范围。
3. `calculator`、`time_parser`、`knowledge_search`、`database_query`、`food_log_writer`、`plan_validator` 和 `meal_plan.save_plan` 统一进入 Tool Registry；已有业务逻辑只接入治理层，不重写。
4. SQL Planner 支持 `local-stub` 确定性规则和 `local` OpenAI-compatible 模型两种模式。两种模式都必须经过同一 Java SQL Guard，真实模式失败不得自动回退并执行另一条 SQL。
5. 模型 API Key 仅由环境变量或 Secret 注入。管理后台只能显示配置状态或脱敏指纹，不能录入、读取、回显或导出明文密钥。
6. 后台权限固定为：`operator` 只读；`admin` 管理业务资源；`superadmin` 管理模型路由、价格、全局预算/配额和高风险工具。
7. fixture/mock 模式继续保留用于设计预览；`VITE_AGENT_MODE=real` 只使用真实 API，失败时不得回退 mock。
8. M2-1 `local` 支持 `deterministic` 和 `openai-compatible` 两种 embedding provider：当前业务验证使用本地确定性 provider + Docker Milvus，不需要 API Key；真实兼容服务仅在显式配置 endpoint、API Key 和 model 后切换，真实付费 API 不作为当前门槛。

### S1 Schema Catalog 与 SQL AST Guard

目标：Java 建立不可绕过的只读查询安全边界。

- 只允许单条 `SELECT` 或 `WITH ... SELECT`；禁止写操作、DDL、多语句、注释穿透和未注册函数/表。
- Java 强制注入或验证当前用户过滤，限制行数、时间范围、执行超时和结果字节数。
- 敏感字段不进入 Catalog；结果再次按字段策略脱敏。
- SQL audit 保存问题摘要、SQL、状态、拒绝码、行数和耗时，不保存凭据。

业务验证：允许查询和攻击样例；跨用户、无过滤、敏感字段、写 SQL、多语句全部拒绝。

- `feat(sql): enforce ast read-only guard and user scope`
