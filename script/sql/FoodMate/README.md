# FoodMate 人工 SQL 执行说明

## 执行顺序

1. 在目标库确认数据库名、账号、PostgreSQL 版本和当前脚本版本。
2. 按 `baseline/` 中的基线脚本完成空环境初始化；已有环境不得重复执行基线。
3. 按版本号顺序执行 `migration/` 中的增量脚本，从 V2 到当前最高版本 V33。
4. 对具备配套校验的迁移，完成后执行同名 `validation/` 脚本并保存只读结果；历史迁移的配套状态以 `migration/README.md` 的矩阵为准。
5. 需要测试数据时，最后按需执行 `seed/`，并执行对应 seed validation。

迁移文件是唯一的结构变更来源。文件已经执行后不得原地修改；修正必须新增更高版本的迁移。目录中的 `rollback/` 只提供经评审的回滚前置条件和反向 SQL，不是故障时的自动恢复机制。

## 人工执行原则

- 当前脚本不会由 Java 启动自动扫描或执行。
- 执行前必须完成可验证的逻辑备份，并记录备份文件、SHA-256、数据库、执行人和开始时间。
- 不执行 `TRUNCATE`、宽泛 `DELETE`、直接修改 Flyway history 或跳过前置条件的回滚。
- 迁移脚本必须保持幂等边界；即使包含 `IF NOT EXISTS`，也必须执行 validation 确认最终结构。
- 生产环境、备份恢复和灾备演练不属于本地业务验证；本目录不能替代发布审批。

## 目录职责

| 目录 | 职责 |
|---|---|
| `baseline/` | 新环境的初始结构和基础约束 |
| `migration/` | 版本递增的人工增量结构变更 |
| `validation/` | 只读结构、索引、约束和业务事实校验 |
| `rollback/` | 回滚前置条件和对应反向 SQL |
| `seed/` | 明确版本的本地或受控业务种子数据 |
| `EXECUTION_RECORD.md` | 每轮实际执行台账和证据摘要 |

## 执行台账

每轮执行都要在 `EXECUTION_RECORD.md` 追加记录：时间和时区、环境、数据库版本、脚本版本、实际命令、validation 结果、保留数据范围、失败与补偿、执行人以及是否清理了本轮随机测试数据。未实际执行的迁移或联调不得写成已完成。

当前版本说明：V16-V17 为 M2-1 公共知识库，V18-V20 和 V30 为 M2-2/M2-3 工具和管理契约，V21-V22 为模型治理，V23 为管理员导出任务，V24-V25 为 DLQ 重放和保留治理，V26 为 M1-4 结构化 Agent 反馈，V27 为 M3 清理执行对账事实，V28 为 M2-1 索引重试 Outbox 事实修正，V29 为 M2-1 Embedding 供应商 Trace 关联事实。详见 `migration/README.md` 及各版本配套 validation/rollback 文件。

本地维护脚本：

- `maintenance/cleanup-local-tool-registry.ps1`：删除无引用的 `e2e_tool_*` 注册残留并重放七个正式工具种子。
- `maintenance/reset-local-business-data.ps1`：备份后清理本地业务/运行时测试事实，保留账号、参考数据和正式工具，并可重建 USDA 营养目录。
- `maintenance/cleanup-local-rag-indexes.ps1`：在 PostgreSQL 没有活动知识文档和切片时，清理公共知识 Milvus/Redis 外部索引；营养 Milvus 集合只做保护性校验。

维护脚本默认只做 dry-run；执行删除前必须使用脚本要求的确认短语，并把实际输出、备份文件和保护范围追加到 `EXECUTION_RECORD.md`。

## 历史迁移配套状态

当前目录是长期演进的人工 SQL 台账。V2 之前及 V3-V12 的部分迁移早于统一目录约定，不能按“每个版本都有可逆 rollback 和 validation”理解；未列出的配套文件不代表迁移未执行。

根目录的 `validation.sql` 是历史兼容校验入口，保留用于已有脚本或人工流程调用；新的版本校验应放在 `validation/`，不要据此认为根目录 SQL 分层缺少配套文件。

| 版本 | validation | rollback | 说明 |
|---|---|---|---|
| V2 | 有 | 有 | 账户与隐私结构 |
| V3-V4 | 无 | 无 | 历史运行时结构；只允许新增高版本修正，不补危险反向删除 |
| V5-V6 | 无 | 有 | 仅保留历史回滚前置条件和脚本，执行前必须人工评审 |
| V7-V12 | 无 | 无 | 历史运行时/记忆兼容结构；通过只读数据库事实确认，不提供通用回滚 |
| V13-V30 | 有 | 有 | 按当前迁移约定维护配套文件；V26-V30 rollback 为只读前置检查 |

对 V3-V12 如需补充校验，只新增只读 validation 文档或更高版本迁移；不得修改已执行迁移，不得为已有数据生成宽泛 `DROP`、`DELETE` 或 `TRUNCATE` 回滚脚本。
